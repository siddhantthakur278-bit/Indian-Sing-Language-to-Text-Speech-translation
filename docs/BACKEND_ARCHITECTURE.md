# Backend architecture

## Sentence processing

`POST /api/sentence` validates the request schema and checks every normalized
gloss against `data/classes.json`. Unknown glosses and `IDLE` return HTTP 400
before NLP, translation, or TTS processing.

The NLP engine resolves the input in this order:

1. Exact emergency templates.
2. Emergency trigger/heuristic handling.
3. Ordinary exact templates.
4. Ordinary dynamic heuristics.
5. Optional Gemini generation for non-emergency unmatched sequences.
6. Safe deterministic gloss text if generation is absent or unavailable.

Emergency triggers are handled locally; no emergency sequence is sent to Gemini.
Emergency wording/classification still requires ISL-domain-expert review before
being treated as verified communication.

## Translation and speech

The translation adapter implements a provider interface. The active provider
looks up existing Hindi and Marathi translations from `data/gloss_pairs.csv`.
Unknown pairs return the English source unchanged. The cache for successful
translations is bounded and thread-safe. Bhashini is not wired because a
deployment-specific pipeline ID and credentials are not configured.

The TTS adapter reports browser speech synthesis as its fallback. No cloud TTS
audio URL is generated by the current backend.

## API operations

The in-process sliding-window rate limiter applies the configured
`RATE_LIMIT_PER_MIN` limit to both POST routes and keys clients by direct ASGI
peer address. It deliberately ignores arbitrary forwarding headers. Its state,
like the bounded sentence-response cache, is per process and resets on restart.

`GET /health` reports liveness and feature modes without returning credentials.
See [API reference](./API.md) and [backend configuration](./BACKEND_CONFIGURATION.md).

## Privacy

The camera stream and video frames are not accepted by backend endpoints. Gloss
text may be sent to Gemini only when the optional provider is configured and the
input is non-emergency. See [privacy notes](./PRIVACY.md).
